迭代链 3 · 评委人设 Prompt 与多智能体编排引擎

本链展示意图控制策略的核心设计过程，以及一次真实的类型系统 Bug 引导修复。
👤 人类（参赛者意图 · 核心约束）
「五位评委要有真实人格差异，问题必须锚定论文真实内容不许编造；评委要能看到彼此的问答记录、不许问重复问题；压力模式下末轮要有连环追问。评分用 JSON 模式，主席最后写结构化终评报告。全程流式，中途可以中止并直接跳去评分。」
🤖 AI 实现要点（roles.ts）
四位评委覆盖正交评审维度（防同质化发言）：
  严正声·方法严谨 | 温文澜·表达理解 | 石力行·落地价值 | 芮敏·前沿创新

System Prompt「提问纪律」五条：
  ① 锚定真实：问题必须建立在检索片段之上，严禁编造
  ② 一次一问 ③ 禁止重复（参考答辩记录）④ 联动深挖 ⑤ 直入主题
  ⑥ 压力模式条件分支（同一人设两种尖锐度）

答辩人 Prompt：忠于论文 / 坦诚边界 / 结论先行 150-300字
🤖 AI 实现要点（engine.ts）
状态机：开场→N轮×4评委质询→(压力追问)→JSON评分→主席终评
- 每问检索 Top-4 片段注入上下文（查询串=评委关注维度/前问+前答）
- 答辩记录滑动窗口压缩至 2.8K 字符（保头保尾）
- AbortController 全链路贯穿；网络错误自动重试一次（Key类错误不重试）
🤖 编译报错（真实踩坑）
engine.ts(470,14): error TS1345: An expression of type 'void' cannot be tested for truthiness.
原因：askJudge 首版签名是 Promise<void>，主循环却写了 const q = await askJudge(...); if (!q) continue。
👤 人类（修复引导）
「让它返回问题消息本身，主循环直接拿返回值去驱动答辩人作答——顺便把点击开始后画布切换的白屏间隙也处理掉。」
🤖 AI 修复
① askJudge 签名 → Promise<ArenaMessage | null>，直接返回 streamToMessage 结果
② 引擎启动初始 patch 立即置 phase='opening'，UI 无缝切换无白屏
✅ 验证结果：Mock E2E 全链路（开场→8问8答→4评分→终评2317字→历史）零错误；真实 Key 答辩 85 秒完整跑通，评委问题全部带片段引用标注。

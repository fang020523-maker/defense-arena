👤 人类（参赛者意图）
「搭好前后端骨架。后端做一个 Express 代理把 DeepSeek 的 SSE 流原样转发给前端，API Key 让用户在前端填自己的，服务端只做白名单透传，不要把我的 Key 硬编码进代码。」
🤖 AI 实现
设计单文件代理 server/index.mjs（约150行）： 
- POST /api/chat：字段白名单透传（model/messages/temperature/max_tokens/top_p）
- Key 三级来源：请求头 x-api-key > 环境变量 DEEPSEEK_API_KEY > 400
- 上游 fetch(stream:true) → res.write() 逐块转发 SSE
- 客户端断开时 res.on('close') 同步 abort 上游（AbortController）
- GET /api/health 健康检查；生产模式托管 dist 静态资源
👤 人类（验收引导 · 评分功能需求）
「评分环节要模型输出严格 JSON，前端要传 response_format；评委输出偶尔会带 ```json 代码块包裹，双端都要兜住，不能让一次脏输出毁掉整场答辩。」
🤖 AI 修复迭代
三重防御： 
① 服务端白名单放行 response_format（仅 {type:'json_object'}，防请求体注入）
② 上游 401/402/429/超时错误码 → 中文提示（"余额不足""触发限流"…）
③ 前端 extractJson()：剥离 ```json 包裹 → indexOf('{')…lastIndexOf('}') 截取 → 解析
另发现 deepseek-reasoner 不支持 response_format（会 400）——评分调用在客户端按模型自动降级为 extractJson 兜底（提交 5cc3483）。
✅ 验证结果：无 Key 调用返回 401 中文提示 ✓；Mock 与真实 Key 全链路 SSE 转发 ✓；评分 JSON 在 4 份评委输出中 100% 解析成功 ✓

本链是「用自动化验证引导 AI 修 Bug」的完整范例：人工审计未发现的两个缺陷，被零成本 E2E 当场揪出。
👤 人类（验证指令）
「依据审查表和流程过程全面对我们的内容进行一次审计，检查核验有什么地方不足。」→ 修复批次后：「你可以自己去找一些毕业论文，然后自己进行论文的验证。」
🤖 AI 构建三层验证设施
① scripts/validate-rag.ts（npm run test:rag）：真实论文语料离线断言
② scripts/mock-llm.mjs：OpenAI兼容SSE Mock（区分质询/作答/评分/终评）
③ server 支持 DEEPSEEK_BASE_URL 覆盖 → 本地Mock零成本跑通全流程
   （该能力同时服务自建网关用户）
🤖 E2E 发现缺陷 #1（现象）
Mock 全流程跑完：phase=done、历史已存、雷达正常——但 store.verdict 恒为空，报告弹窗永远显示「报告生成中…」，导出缺失主席终评。
👤 人类（修复引导）
「E2E 能发现人工审计漏掉的问题，很好。顺着调用链查终评结果的去向，两处调用点都补上，别只修一处。」
🤖 AI 根因修复
根因：runVerdict 返回值只传给了 saveSession，漏 patch({verdict})
修复：runArena 与 runScoringOnly 终态 patch 均补 verdict 写入
🤖 E2E 发现缺陷 #2（诡异现象）
store 里 phase=questioning，DOM 却停留在向导页，零 JS 错误。页面注入探针实测：1 秒 0 个 requestAnimationFrame 回调（渲染管线暂停）→ framer-motion AnimatePresence mode="wait" 的退出动画永远等不到帧，新分支被无限期阻塞。真实用户在后台标签页同样会触发此冻结。
🤖 AI 修复
改同步挂载（去掉 mode="wait"，initial={false}）：
动画仅作视觉过渡，不再阻塞分支切换 → 后台标签页不再冻结
连带加固：vite optimizeDeps 预声明懒加载依赖
（消除"运行中依赖优化→整页reload→内存态清空"干扰源）
✅ 验证结果：修复后 Mock E2E 全绿（4问4答/4评分/雷达/472字终评/历史，0 JS 错误）；随后真实 Key 全流程 85 秒跑通。
